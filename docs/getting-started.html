AIRT Harness - Getting Started

One canonical, OpenAI-compatible API in front of any target - mock or live - with sessions, an integrated guardrail, recorded evidence, and replay. Here's what to run.

🖥️ On the course VM everything is pre-installed under /opt/airt/src - no git, no sudo. Use python (the course venv is on your PATH). The authoritative profile list for your image is ~/labs/PROFILES.txt.
New to the framework? See how the canonical API, the firewall, recording and replay fit together. Why AIRT Harness →

First - check the VM

Before anything else, run the self-check (or the “Check this VM” menu item). It boots each target briefly, prints PASS/FAIL, and shows an image-identity block naming the harness and governance refs - paste that block if you ever report a problem.

airt-selfcheck

Run a target

Each target needs its tool server (the database behind the flags) and then the mock. The two CTF tool servers use different ports, so they never clash.

Larkfield OWASP LLM Top 10

A deliberately-vulnerable retail support assistant. Twelve OWASP{…} flags across nine of the ten OWASP LLM categories. All data synthetic.

cd /opt/airt/src/airt_harness
python vendor/larkfield-db-mcp/server.py --port 8200 --version 1.0.2 &
python -m harness.mock --profile profiles/deepcyber-ctf/profile.yaml --port 8080

Deep Vault Capital Agentic · FCA

An agentic financial-adviser with a real tool surface and FCA boundaries. DVC{…} / FCA{…} flags fire on a real database effect. Two postures - unsecured and hardened.

cd /opt/airt/src/airt_harness
python vendor/dvc-db-mcp/server.py --port 8210 &
python -m harness.mock --profile profiles/deepvault-capital/profile.yaml --port 8080
# hardened: add --system-prompt profiles/deepvault-capital/mock/system_prompt_hardened.txt

DeepTrace Investigations Runtime governance

A Cedar policy allows / denies / escalates each tool action deterministically. Separate checkout, so cd into it first.

cd /opt/airt/src/airt_governance
python -m harness.mock --profile profiles/investigations/profile.yaml --port 8091

Run one CTF mock at a time (both use 8080); governance runs alongside on 8091. Pick the backing model with the GUI dropdown or POST /model - only models whose key is in .env appear (see MODELS-SETUP.md); echo needs no key.

Talk to it & red-team it

You started the target on :8080 - talk to it there. (The OpenAI-compatible /v1/chat/completions front is the canonical proxy on :8000; run uvicorn harness.server:app --port 8000 to point an OpenAI tool at it.)

Send a message (or the OpenAI-compatible /v1/chat/completions)

curl -X POST http://localhost:8080/chat -H "Content-Type: application/json" \
  -d '{"input": "What is an ISA?"}'

Toggle the HumanBound firewall (guardrail), then re-run the same attacks

curl -X POST http://localhost:8080/firewall -d '{"enabled": true}'

Replay recorded sessions against the current target

airt-replay profiles/default/intel/ --list-sessions
airt-replay profiles/default/intel/ --session abc123 -o results/replay.md

Sessions use the x-session-id header; every request/response is recorded as JSONL (mock-audit.jsonl). More on how this fits together →
