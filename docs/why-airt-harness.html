Deep Cyber · AI Red Teaming Framework

Why AIRT Harness

One canonical API in front of any target, so every red-teaming tool, every model, and every CTF profile speaks the same wire format and produces the same evidence. Develop against a local mock, then flip to a live API with one environment variable.

Architecture

red-team tool ─┐ your curl ├──► CANONICAL PROXY ──► TARGET PyRIT / promptfoo ┘ harness.server # a local MOCK (a profile), or :8000 # a real LLM API (OpenAI, Gemini, /v1/chat/completions # Bedrock, Ollama …) - swapped /chat # in by one env var + sessions, firewall, MOCK = harness.mock (:8080) recording, replay

Canonical proxy (harness/server.py, port 8000) exposes an OpenAI-compatible /v1/chat/completions and a simplified /chat. Message mappers translate between the canonical format and whatever the target speaks. The target is either a mock (a profile's deliberately-vulnerable app) or a real API - same proxy, same evidence, either way.

One canonical API

Every tool hits the same /v1/chat/completions - no per-target glue.

Standardised evidence

Every request/response captured as JSONL with a tamper-evident audit trail.

Profiles + local mocks

Develop and rehearse without burning target budget or hitting a live system.

Mock ⇄ live switch

Flip from mock to the real API with one env var. Cloud, on-prem or local.

Broad model support

OpenAI, Anthropic, Gemini, Bedrock, Ollama, and echo.

Docker-native, open source

Single container, no host Python needed.

What you get

Profiles. A profile is a profile.yaml declaring a target: identity, endpoint, request/response mapping, auth, session handling, an optional policy, and (for a mock) the app's behaviour. Switching targets is switching profiles.

The canonical, OpenAI-compatible endpoint. Point any OpenAI-compatible client at :8000/v1/chat/completions (or the simpler /chat):

curl -X POST http://localhost:8000/chat -H "Content-Type: application/json" \
  -d '{"input": "What is an ISA?"}'

Sessions. Multi-turn conversations are kept per session with the x-session-id header - this is what lets multi-turn attacks (PAIR/TAP/GOAT/Crescendo) hold a conversation.

Model switching. The mock is backed by a real model from the catalogue - swap it live with POST /model or the GUI dropdown, or set it at launch with MOCK_BACKEND (echo, openai, gemini, bedrock, ollama).

Integrated guardrails (HumanBound firewall). A guardrail sits in front of the target, off by default - toggle it at runtime and run the same attacks off, then on:

curl -X POST http://localhost:8000/firewall -d '{"enabled": true}'

Recording. Every request/response is captured to JSONL (mock-audit.jsonl) - the standardised evidence every tool then shares.

Replay. airt-replay re-runs recorded sessions against the current target - regression testing on the same API, with an optional LLM-judge score per turn. A/B the firewall, catch silent guardrail drift in CI, feed findings into posture management / AI SecOps.

airt-replay profiles/default/intel/ --session abc123 -o results/replay.md
